# 결정 로그

새로운 결정이 생길 때마다 날짜순으로 아래에 추가한다.

## 2026-08-09
- 게임 컨셉 확정: 2D 탑뷰, 칸 기반 턴제 전술 전투 + 마을/던전 순환 구조 + 관계 시스템 중심 RPG.
- 핵심 축 2가지로 확정: (1) NPC/단체 관계 시스템, (2) 던전 탐사.
- 전투 비주얼 레퍼런스: 건담 G 이터널.
- 비주얼 스타일 지향점: 옥토패스 트래블러류 2.5D (다만 1인 개발 역량상 2D로 시작).
- 엔진 결정: **Godot 4** (이유는 [[04_tech_stack]] 참고). 개발자는 Godot 최초 사용, C++ 경험 있음.
- 프로젝트 문서 체계(`docs/`) 및 Godot 프로젝트 뼈대 생성.
- 던전 생성 방식 결정: **하이브리드** (구조/몬스터/함정 절차적 생성 + 관계 기반 NPC 조우는 별도 레이어). — [[02_dungeon_town_structure]]
- 던전 NPC를 랜덤 NPC(비네임드, 성향 기반)와 테이블/트리거형 NPC(네임드·소속 집단, 조건부 등장) 두 종류로 분류. — [[02_dungeon_town_structure]]
- 랜덤 NPC "승격" 메커니즘 채택: 플레이어와 유의미한 상호작용을 겪은 랜덤 NPC가 네임드/테이블-트리거 NPC로 전환되어 이후 재조우 가능 (네메시스 시스템 참고). — [[01_relationship_system]]
- 개인 특성(Trait) 시스템 컨셉 채택: 관계와 별개로 탐욕/이타심/공포내성 등 성격 수치를 NPC에 부여, 상황에 따른 배신/도주 등 돌발 행동에 사용. 세부 공식은 미정. — [[01_relationship_system]]
- 관계-특성 상호작용 확정: 돌발 행동 발생 확률은 특성 단독이 아니라 특성×관계 조합으로 결정 (관계가 좋으면 배신 확률 감소). — [[01_relationship_system]]
- 특성 가변성 확정: 네임드 NPC는 서사를 통해 특성이 변화(성장 아크 가능), 랜덤 NPC는 고정. — [[01_relationship_system]]
- 노출 방향 확정: 관계도는 플레이어에게 노출(정확한 수치 vs 등급 표시는 미정), 개인 특성은 기본 비공개 후 관계도가 매우 높아지거나 특정 아이템/스킬로 확인. — [[01_relationship_system]]
- 유파(스킬 계열) 시스템 컨셉 채택 (세키로 영감): 공용 스킬 + 유파 전속 스킬 이원화, 유파 중복 입문 가능(일부는 조건부), 숙련도로 상위 스킬 해금, 스킬 슬롯(기본안 4개)은 던전 진입 전 마을에서 고정하며 던전 내 변경 불가, 고위 기술은 하나의 유파만 슬롯에 장착 가능(저위/공용은 자유 혼합). — [[06_skill_style_system]]
- 스킬 구성 요소 확정 (다크소울 영감): 스킬은 데미지/사정거리/효과로 구성, 스킬마다 영향받는 스탯과 스탯별 스케일링 등급이 다름 (예: 힘 A급/기량 C급). 실제 스탯 목록은 미정. — [[06_skill_style_system]]
- 세계관 톤 확정: 던전 밖(밝고 인간적) vs 던전 안(차갑고 인간 불신, 죽음이 무의미)의 강한 대비. 다크소울류의 전면적 암울함은 지향점 아님. 사람들이 던전에 들어가는 이유는 미정. — [[00_game_overview]], [[07_progression_death_system]]
- 진행 구조 확정: 런 기반 로그라이크 + 익스트랙션. 특정 층/장소에서 마을로 귀환 가능, 던전에서 사망 시 소지 아이템 전부 상실, 다음 런에서 사망 지점 아이템 회수 가능. — [[07_progression_death_system]]
- 플레이어 캐릭터 특수성 확정: 던전에서 죽어도 마을로 돌아올 수 있는 것은 플레이어뿐, 파티원/다른 NPC는 진짜로 죽음. 이유는 세계관 설정 과제로 남김. — [[07_progression_death_system]]
- 파티원 사망 처리: 퍼머데스/부상 복귀 여부는 "상황에 따라 다름"으로 방향만 결정, 조건은 미정. — [[07_progression_death_system]]
- 주인공 정체성 확정: 커스터마이징 아바타, 전투 직접 참전 (지휘관형 아님). — [[00_game_overview]]
- 던전 기원 확정: 초월적 존재가 만든 공간 + 고대 유적 + 외부 세계 요소의 혼합. — [[08_world_and_factions]]
- 던전 입장 동기 확정(기본형): 희귀 자원/재화. 보물·몬스터 부산물이 외부 세계에서 다양하게 활용됨. 깊이 내려갈수록 보상↑, 몬스터 강함↑ (위험-보상 스케일링, 런/익스트랙션 구조와 연동). — [[08_world_and_factions]], [[07_progression_death_system]]
- 세력(단체) 성격 방향 확정: 집단마다 뚜렷이 다른 성격. 예시로 탐험가 집단/외부로 못 나가는 범죄자 집단/던전의 진실을 파헤치는 집단/종교적 목표로 종군하는 이들/귀족가 지원 탐사대/강함 자체를 연구하는 이들 등이 나옴 (최종 목록 아님). — [[08_world_and_factions]]

## 2026-08-09 (개발 환경 및 전투 시스템 상세화)
- 개발 환경: Godot 4.7.1 설치 완료(winget). git init, 실제 구현은 아직 미착수.
- 던전 내 이동 방식 확정: 탐사는 자유 이동(8방향), 적과 시야 접촉 시(필드 조우식) 심리스하게 그리드 전투로 전환(별도 로딩 없이 현재 필드가 그대로 전투 그리드가 됨). — [[02_dungeon_town_structure]], [[03_combat_system]]
- 파티 규모 확정: 초반 소규모(2~3명) → 중반 중규모(4~6명)로 성장, 솔로 플레이도 지원(자체 하드모드). 몬스터 수는 파티보다 많을 수 있음. — [[03_combat_system]]
- 그리드 크기 방향: 유닛 수/환경에 따라 가변, 최소 중형 이상. 정확한 치수는 미정. — [[03_combat_system]]
- 턴 순서 확정: 개별 유닛 속도 스탯 기반 우선순위(초리어티) 큐. — [[03_combat_system]]
- 사거리/시야 확정: 엄폐 구현 + 단순화된 고저차(1/2/3단), 고지대 원거리 공격에 사거리·명중 보너스, 등반 시 이동력 2배 소모. 부담이 크면 고저차는 빼고 엄폐만 남기는 것도 대안. — [[03_combat_system]]
- 지형 효과 확정: 이동 방해 지형 + 상태이상 지형(장판) + 아이템으로 칸 상태를 일시 변경하는 시스템, 그리드 칸 단위 상태 저장 전제. — [[03_combat_system]]
- 스탯 체계 방향: 다크소울류 중간 규모(6~8개) 스탯. 정확한 목록은 [[06_skill_style_system]] 스킬 스케일링과 함께 추후 확정. — [[03_combat_system]]
- 관계 수치 구조 확정: 개인 + 소속 단체 이중구조. 단체 평판이 소속 NPC 전원의 초기 호감도에 가중치를 줌. 정확한 계산식은 미정. — [[01_relationship_system]]
- 스킬 계열 확정: 순수 물리/기술 + 기존 마법류 + 던전 기원 신마법류의 3계열 체계. 던전 기원 신마법은 세계관의 초월적 던전 기원과 직결. — [[06_skill_style_system]], [[08_world_and_factions]]

## 2026-08-10
- 스탯 목록 핵심 6개 확정: **체력 / 힘 / 기량 / 지능 / 신앙 / 신비**. 물리 계열은 체력/힘/기량, 기존 마법류는 지능/신앙(유파마다 비중 다름), 던전 기원 신마법류는 신비 비중이 상대적으로 높은 경향(전용은 아님). 7~8개로 확장할지는 미정. — [[03_combat_system]], [[06_skill_style_system]]
- 유파 규모 확정: 초기 출시 기준 소규모(총 6~9개, 계열당 2~3개). 1인 개발 콘텐츠 부담을 고려, 출시 후 확장 가능한 구조를 전제로 함. 구체적 유파 이름/컨셉은 미정. — [[06_skill_style_system]]
- 비주얼 스타일 방향 수정: "2D로 시작 후 여력되면 2.5D 검토"에서 **처음부터 2.5D(HD-2D) 지향**으로 변경. 캐릭터는 2D 도트 스프라이트 유지 + 동적 그림자, 일부 배경/외부 요소는 3D처럼 보이도록 연출. 엔진이 결국 2D 기반이라 전부 시각적 트릭(SubViewport + 3D 라이팅 조합 등)에 의존하는 것을 전제로 함. 어느 요소를 3D로 처리할지 등 세부 구현 방식은 미정. — [[00_game_overview]], [[04_tech_stack]]
- 아트 파이프라인 확정(뒤늦게 문서화, 결정 자체는 이전 세션에서 확정됨): 베이스 스프라이트는 픽셀아트, 네임드 NPC는 대화용 페인팅 버스트 초상화를 별도 트랙으로 제작(AI 보조). 도구는 Aseprite + `pixel-plugin`(Aseprite MCP) 조합. 명령어/팔레트 설명은 신규 문서로 분리. — [[09_aseprite_pixel_pipeline]]

## 2026-08-11
- 플레이어 사망 시 귀환 가능한 이유 확정: **"세계 충돌" 이론.** 던전과 결부된 초월적 존재가 주인공을 낙점, 주인공이 던전에서 사망하면 그 세계선에서는 진짜로 죽되, 초월적 존재가 주인공이 죽지 않은 다른 세계선을 억지로 충돌·융합시켜 살림 — 이 과정에서 살아있던 세계선 쪽 의식은 지워짐. 그 런에서 쓴 장비/소비 아이템/재화가 복구되지 않는 것은 이 충돌의 부작용으로 자연스럽게 설명됨(마을 자원이 "안 쓴 셈"으로 되돌아가지 않음). 파티원/다른 NPC는 낙점 대상이 아니므로 진짜로 죽는 기존 비대칭과 정합. 왜 하필 주인공을 택했는지, 지워지는 의식의 윤리적 함의, 이 현상이 다른 존재에게 알려지는지는 의도적으로 미스터리로 남김. — [[07_progression_death_system]], [[08_world_and_factions]]
- Godot 구현 착수: 씬 전환(마을↔던전, `GameManager`가 컨테이너 스왑), 3D 오블리크 카메라(직교 투영, 25도 — 첫 시도값인 35도에서 낮춤) + 빌보드 스프라이트 캐릭터로 세계 렌더링 구조 확정(평평한 2D+가짜 그림자 대신 실제 3D 지형 채택 — 이미 확정된 고저차/엄폐 전투 규칙을 자연스럽게 구현하기 위함). 카메라는 Player의 자식으로 둬서 씬 불문 자동 추적. 마을/던전 각각 위치 기반 상호작용 지점(진입/추출 지점)에서만 씬 전환 가능하도록 구현 — 기존 "특정 장소에서만 귀환 가능" 규칙과 일치. 정식 키 바인딩은 보류, Godot 기본 `ui_*` 액션으로 임시 구현(TODO로 코드에 표시). — [[03_combat_system]], [[07_progression_death_system]]
- 관계 수치 세부 구조 확정: 단일 스칼라(v1, 다차원으로 확장 가능하게 구조화), 개인 호감도는 "씨앗(첫 만남 시 단체 평판 반영) + 지속적 견인(이후 단체 평판 변화에 다소 끌려가되, 개인 호감도가 중립에서 멀수록 저항 커짐)" 하이브리드로 결정. 극값(±100)에서 단체 평판 영향에 사실상 면역되는 것은 의도된 동작(단, 극값 도달이 실제로 어렵게 밸런싱됐을 때만 타당 — 밸런싱 재검토 여지 있음). 정확한 씨앗 가중치/견인 곡선 수치는 밸런싱 영역이라 미정, 구현 시 별도 함수로 분리. 개인 특성(탐욕/이타심 등)은 관계 데이터가 아니라 NPC 자체 데이터에 별도로 둠. — [[01_relationship_system]]

- **인벤토리 시스템 설계 확정**(신규 문서 [[10_inventory_system]]): 형태는 그리드/나열식 대신 **자유 배치형**(울티마 온라인류, 겹침 방지 없음). 용량은 슬롯 개수가 아니라 **무게 총합**으로 제한하고, 초과 시 실질 속도에 페널티(`CombatFormulas.effective_speed()`의 `equipment_modifier` 자리와 연결 예정). **전투 중 투척** 확정: 인벤토리 아이템을 그리드 타일로 드래그하면 그 위치에 던짐(`Grid.raycast_to_cell()` 재사용). **인접 배치 위험**(불+폭탄=폭발, 날카로움+물약=파손 등) 방향 확정 — 배치 자체를 막지 않고 실제로 결과가 발생하게 하되(세계관의 하드코어 톤과 일치시키기 위함, 사용자가 던전 탐험을 더 하드코어하게 만들고 싶어함), 완전히 예측 불가능하지 않도록 아이템 태그/경고 UI로 "주의하면 피할 수 있었다"는 학습 곡선을 의도함. 세부(태그 목록, 규칙 테이블, 경고 UI 형태, 무게/투척 수치)는 전부 미정. — [[03_combat_system]], [[07_progression_death_system]]
- Godot 구현: **인벤토리 UI를 텍스트 나열에서 실제 자유 배치 UI로 교체.** `InventorySlotIcon`(드래그 가능한 개별 아이템 아이콘) + `InventoryPanel`의 `Bag` 영역(자유 배치 컨테이너)으로 구성. 아이템 아이콘 리소스가 없어서 `item.icon`이 비어있으면 **일반 색상 사각형으로 대체**하는 폴백을 넣음(뼛조각 등 지금 아이템 전부 해당) — 나중에 진짜 아이콘이 생기면 `ItemData.icon`만 채우면 자동으로 전환됨, 코드 변경 불필요. 드래그는 Godot 기본 Control 드래그 API 대신 **직접 구현**(마우스 down/motion/up 수동 처리) — 나중에 전투 그리드 타일 위로 드롭하는 것도 처리해야 하는데, 이건 다른 Control이 아니라 3D 월드 좌표로 드롭하는 거라 Godot 기본 DnD로는 못 다룸. `Inventory.slots`에 **`slot_id`**(스택별 안정적 식별자, 배열 인덱스는 슬롯이 추가/제거되며 밀려서 UI가 위치를 추적하기에 부적합) 추가 — UI가 슬롯 위치를 `slot_id` 기준으로 저장. 겹침 방지 없음(설계대로), 패널 밖으로 드래그하면 패널 안으로 클램프. 전투 중 투척은 아직 미연결(`_on_icon_drag_ended`에 TODO로 표시) — 다음 작업. — [[10_inventory_system]]
- Godot 구현: **전투 중 투척 연결.** `ItemData`에 `throwable`(옵트인 불리언) + `throw_damage`(고정 데미지, `basic_attack_damage()`와 같은 성격의 플레이스홀더) 추가, 뼛조각을 테스트용으로 던질 수 있게 설정. `InventoryPanel`이 인벤토리 패널 바깥으로 드롭된 걸 감지하면(`_bag`의 화면 영역 밖 + 전투 중 + 아이템이 throwable) `Grid.raycast_to_cell()`로 드롭 위치를 셀로 변환해 `item_throw_requested` 시그널만 쏘고, 실제 효과(그 칸에 적이 있으면 데미지 적용)는 `Dungeon.gd`가 처리 — UI는 "의도"만 알리고 게임 로직은 씬이 담당하는 분리 유지. **빗나가도 아이템/턴은 소모됨**(하드코어 톤 유지). `_do_attack()`과 던지기가 턴 진행 로직(적 턴 통과 처리)을 공유하도록 `_advance_past_enemy_turn()`으로 리팩터링해서 중복 제거. 헤드리스 테스트로 명중/빗맞음/전투 밖 무시/반복 투척으로 실제 처치까지 전부 검증. — [[10_inventory_system]]

- **버그 진단**: "스켈레톤 잡고 마을 갔다가 다시 던전 가서 아이템 던졌더니 갑자기 마을로 이동됨" 버그 리포트. 원인은 승리 후 HP를 회복시키는 코드가 어디에도 없다는 것 — `Player.heal_to_full()`은 `Dungeon._handle_player_defeat()`(패배 시 "생존 후퇴" 처리)에서만 호출됨. `Player` 노드는 씬 전환 때 파괴되지 않고 재부모화만 되므로 `current_hp`는 마을을 거쳐도 그대로 유지되는데, 전투 중이 아니면 HP를 볼 방법이 전혀 없어서(라벨이 전투 모드 UI에만 있음) 첫 전투에서 입은 데미지가 조용히 누적되다가 두 번째 전투에서 반격 한 번(이번엔 투척으로 트리거된 몬스터 턴)에 HP가 0이 되어 예고 없이 "패배" 처리된 것. HP가 승리해도 자동 회복되지 않는 것 자체는 하드코어 톤과 부합하는 의도된 설계로 볼 수 있음 — 진짜 문제는 **가시성 부재**였음.
