# 기술 스택

## 엔진: Godot 4
**결정됨 (2026-08-09)**

### 선택 이유
- **가벼움**: Unity 대비 설치 용량, 빌드 파이프라인, 라이선스 부담이 적음. "너무 무거운 툴은 쓰고 싶지 않다"는 요구사항에 부합.
- **2D 탑뷰/그리드 지원**: TileMap, 2D 애니메이션 등 필요한 기능이 기본 내장. 2.5D(옥토패스 트래블러류) 연출을 SubViewport + 3D 라이팅 조합으로 처음부터 목표로 함 — 캐릭터는 2D 스프라이트 유지, 동적 그림자와 일부 배경/외부 요소의 3D 표현에 활용. 세부 구현 방식(어느 요소를 3D로 할지 등)은 미정.
- **플랫폼 유연성**: 같은 프로젝트에서 Windows 데스크톱과 HTML5(웹 브라우저) export를 모두 지원 → 플랫폼(웹 vs 앱)을 아직 정하지 못한 현재 상황에서 결정을 늦출 수 있음.
- **콘텐츠 반복 속도**: 관계 시스템처럼 콘텐츠(대사, 분기, NPC 반응)가 많은 부분은 엔진 성능보다 반복 제작 속도가 중요 → GDScript의 빠른 반복 사이클이 유리.

### 언어
- **주 언어: GDScript** — 관계 시스템, 다이얼로그, 게임 로직 등 콘텐츠 중심 코드에 사용.
- **필요시: GDExtension(C++)** — 던전 절차 생성 알고리즘 등 연산이 무거운 부분에 한해 C++ 모듈을 붙이는 것을 고려. 개발자가 C++에 익숙하므로 진입 장벽 낮음.
- 순수 C++ 자체 엔진(SDL2/SFML 등)은 기각 — UI, 세이브 시스템, 다이얼로그 트리 등을 전부 직접 구현해야 해서 1인 개발 시간 대비 핵심 기능(관계 시스템)에 쓸 시간이 줄어든다는 판단.

## 플랫폼
- 기본: PC
- 웹 브라우저 vs 데스크톱 앱: **미정.** Godot의 동시 export 기능을 활용해 프로토타입 단계에서는 웹으로 빠르게 테스트하고, 정식 결정은 추후로 미룸.
