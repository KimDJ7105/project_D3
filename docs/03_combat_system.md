# 전투 시스템

## 형식
2D 탑뷰(2.5D 연출), **자유 이동 기반** 턴제 전술 전투. 원래는 칸(그리드) 기반으로 시작했으나 2026-08-18에 자유 이동으로 전환 — 아래 "전투 중 이동과 스테미나" 참고.

## 비주얼/연출 레퍼런스
건담 G 이터널의 전투 화면과 유사한 구도를 목표로 함 (탑뷰 위 유닛 배치, 턴제 진행). 다만 그리드를 버리고 자유 이동+스테미나 기반으로 가면서 순수 그리드 전술물보다는 액션-전술 하이브리드에 가까운 느낌으로 옮겨감 — 애초에 그리드는 별 고민 없이 정한 초기값이었을 뿐 지켜야 할 취향적 이유는 없었다고 확인함(2026-08-18).

## 탐사 ↔ 전투 전환 (결정됨 — 2026-08-09, 전투 방식 2026-08-18 갱신)
던전 탐사는 자유 이동(8방향)으로 진행하다가, 전투 진입 시 턴제 전투로 전환된다. 탐사와 전투 모두 자유 이동이라는 점은 같지만, 전투 중에는 턴 순서·스테미나 제한이 걸린다(아래 참고).
- **진입 트리거**: 필드 조우식(시야 접촉). 탐사 중 적이 필드에 보이고 플레이어(또는 적)의 시야에 포착되면 전투 개시.
- **전환 방식**: 심리스. 별도 로딩/화면 전환 없이, 현재 필드에서 보이던 그 영역이 그대로 전투 공간으로 재구성된다 (크로노 트리거류).
- 이 구조는 [[02_dungeon_town_structure]] 의 마을-던전 루프, 던전 내 랜덤/네임드 NPC 조우([[01_relationship_system]])와 직접 연결됨.

## 파티 규모 (결정됨 — 2026-08-09)
- 플레이어 파티(플레이어 + 동료 NPC) 기준, 초반은 소규모(2~3명), 중반부터는 중규모(4~6명)로 커지는 성장 곡선.
- 솔로 플레이도 가능해야 함 — 파티원 없이 진행하는 자체 하드모드 성격.
- 몬스터 측 유닛 수는 플레이어 파티보다 많을 수 있음(비대칭 인원수 허용).

## 전투 중 이동과 스테미나 (그리드 폐기, 확정 — 2026-08-18)
기존엔 전투를 칸(그리드) 기반으로 진행할 계획이었으나, **자유 이동(연속 좌표) 기반으로 전환**하기로 확정. 전환 사유:
- 스킬 시스템([[06_skill_style_system]])도 던전 절차적 생성([[02_dungeon_town_structure]])도 아직 코드가 하나도 없는 시점 — 둘 다 그리드를 전제로 먼저 만들면 나중에 다시 만들어야 했을 것. 지금이 전환 비용이 가장 낮은 시점.
- 클릭 이동에 경로탐색(장애물 회피)이 필요한 건 그리드였어도 마찬가지였을 것(칸 A→B 이동도 결국 길찾기가 필요) — 그리드를 유지해서 얻는 이득이 생각보다 적었음.
- 엄폐/시야를 실제 3D 지오메트리에 레이캐스트로 판정하는 게 그리드 셀 플래그로 관리하는 것보다 자연스러움.

**이동 방식**: 전투 중에도 그리드 스냅 없이 클릭한 지점으로 이동(구현 완료 — 2026-09-16). 클릭 지점이 스테미나로 갈 수 있는 거리보다 멀면 거부하지 않고 갈 수 있는 만큼만 이동(클램프). 지금은 장애물이 없는 씬이라 직선 이동으로 구현했고, 장애물을 피해가는 실제 경로탐색(Godot `NavigationAgent3D`)은 실제 장애물이 있는 던전이 생기면 추가할 예정 — 절차적으로 생성되는 던전이라면 런타임 내비메시 베이킹까지 같이 필요해질 것.

**이동 가능 범위**는 새로 추가된 **스테미나** 스탯으로 제한한다(아래 스탯 체계 참고):
- 전투 중 이동 거리에 비례해 스테미나 소모, 고지대로 오를수록 추가 소모(기존 "등반 시 이동력 2배 소모" 아이디어를 스테미나 소모량 증가로 대체).
- 공격/스킬 사용 시에도 스테미나 소모(스킬마다 비용이 다름).
- **매 턴 시작 시 최대치로 전량 리필**(이월 없음) — 규칙을 단순하게 유지.
- 목적: 이동과 행동을 같은 자원으로 묶어서, 원거리 캐릭터가 "이동→공격→이동→공격"을 매턴 무한 반복(카이팅)하는 걸 자연스럽게 억제하고, 매턴 "얼마나 움직이고 뭘 쓸지"를 전략적으로 고민하게 만듦.
- 이동/스킬별 정확한 소모량, 등반 배율은 다른 수치들처럼 밸런싱 영역 — 미정, 구현 시 별도 함수/테이블로 분리.
- **탐사 중 자유 이동(WASD)에는 스테미나 소모 없음** — 전투 중에만 적용되는 자원.

**턴 구조 변경**: 기존엔 "행동 1회 = 턴 종료"로 단순했는데, 스테미나가 허용하는 한 이동과 행동을 여러 번 섞어 쓸 수 있어야 하므로 **플레이어가 직접 "턴 종료"를 선택해야 턴이 끝나는 구조**로 변경 확정, 구현 완료(`end_turn` 입력 액션, 2026-09-16) — 스테미나가 0이 돼도 자동으로 턴이 끝나지는 않음(수동 종료만 인정, 아래 열린 질문에서 재검토 여지는 남김).

## 턴 순서 (결정됨 — 2026-08-09, 속도 산출 방식 2026-08-13)
개별 유닛의 속도 스탯 기반 우선순위 큐(초리어티 큐, FF택틱스/슬레이 더 스파이어류). 아군/적군 유닛이 속도 순으로 뒤섞여 행동.

전투에 쓰이는 실질 속도는 단일 스탯이 아니라 합성값:
```
실질 속도 = 기본 속도 스탯 + 기량 구간별 보너스(계단식) + 장비 보정
```
- **기량 구간별 보너스**는 기량 수치를 구간(예: 1~10, 11~20 ...)으로 나눠 구간마다 다른 보너스를 더하는 계단식 — 정확한 구간 경계/증가폭은 밸런싱 영역이라 미정, 구현 시 별도 테이블/함수로 분리해 나중에 숫자만 조정 가능하게 함.
- 이 구조 때문에 **속도가 7번째 핵심 스탯으로 확정**됨 (아래 스탯 체계 참고).

## 사거리/시야 — 엄폐 및 고저차 (결정됨 — 2026-08-09, 이동 관련 수치는 2026-08-18 스테미나로 대체)
- **엄폐(커버)**: 구현. 장애물이 시야/공격을 막음 — 그리드 폐기로 셀 플래그 대신 실제 3D 지오메트리 레이캐스트 기반으로 판정할 전망(세부는 열린 질문).
- **고저차**: 단순화된 단계형(1단/2단/3단 등)으로 구현. 복잡한 실시간 높이 계산은 지양.
  - 더 높은 곳에서 원거리 공격 시 사거리 또는 명중률에 보너스.
  - 높은 곳으로 이동(등반)할 때는 ~~이동력을 2배로 소모~~ **스테미나를 추가로 소모**(정확한 배율은 미정 — "전투 중 이동과 스테미나" 참고).
- 1인 개발 부담이 과도하다고 판단되면 고저차는 제거하고 엄폐(장애물)만 남기는 것도 대안으로 열어둠.

## 지형 효과 (결정됨 — 2026-08-09, 그리드 폐기로 저장 방식 갱신 — 2026-08-18)
~~그리드 칸(타일) 단위로 상태를 저장할 수 있는 구조를 전제로~~ 그리드가 없어졌으므로 특정 위치를 중심으로 한 영역(반경/모양)에 상태를 부여하는 구조로 변경(그리드 폐기와 연동, 세부 구현 방식은 미정):
- **이동 방해 지형**: 스테미나 추가 소모 등.
- **상태이상 지형**: 특정 영역에 있으면 상태이상 부여(예: 화상/독 장판).
- **장판 조작**: 아이템으로 특정 영역의 지형 상태를 일시적으로 변경 가능(예: 불 장판을 물로 꺼서 무력화 등).

## 스탯 체계 (핵심 8개 확정 — 2026-08-10 6개 확정, 2026-08-13 속도 추가, 2026-08-18 스테미나 추가)
다크소울류를 계승한 스탯 체계, 핵심 8개로 확정: **체력 / 힘 / 기량 / 지능 / 신앙 / 신비 / 속도 / 스테미나**.
- 체력/힘/기량 — 물리 계열 스킬([[06_skill_style_system]] 참고)의 주 스케일링 대상.
- 지능/신앙 — 기존 마법류 스킬의 주 스케일링 대상. 유파에 따라 지능 위주 vs 지능+신앙 혼합 등 비중이 다름.
- 신비 — 던전 기원 신마법류 스킬에서 더 자주 쓰이는 경향(전용은 아님, 유파별로 비중 다름).
- **속도** — 초리어티 큐(턴 순서)의 기반 스탯. 위 "턴 순서" 섹션 참고, 기량과 장비의 영향을 받아 실질 속도로 합성됨. 턴 순서 결정에만 관여 — 아래 스테미나와 역할이 분리됨.
- **스테미나** — 전투 중 "내 턴에 뭘 할 수 있는지"(이동 범위 + 행동 가능 여부)를 결정하는 자원. 위 "전투 중 이동과 스테미나" 참고. 속도와 별개의 독립적인 핵심 스탯으로 확정 — 속도에 연동시키면 빠른 캐릭터의 가치가 턴 순서+행동력 두 배로 뻥튀기되는 문제가 있어 분리를 선택함.
- 9개 이상으로 추가 확장할지는 미정.

## 관계 시스템과의 연결
전투 자체의 규칙과는 별개로, 관계 시스템이 전투 발생/진행에 개입하는 지점이 있음:
- 관계가 나쁜 세력과의 조우 → 의도치 않은 전투 발생.
- 관계가 좋은 NPC의 난입 지원 → 위기 상황에서 전투 국면 전환.
- 상세 트리거 및 확률은 [[01_relationship_system]] 에서 별도 설계 필요.

## 스킬 시스템
전투 스킬은 [[06_skill_style_system]] 의 유파(스킬 계열) 시스템을 따른다 — 공용 스킬 + 유파 전속 스킬, 던전 진입 전 마을에서 고정하는 스킬 슬롯(기본안 4개) 구조.

**스킬 범위 구조 (확정 — 2026-08-18, 투척에 구현 완료 — 2026-09-16)**: 그리드 폐기에 맞춰 스킬의 범위를 **사거리(시전자 → 목표 지점까지의 최대 거리) + 효과 반경(그 지점을 중심으로 영향을 받는 범위)**의 이원 구조로 통일. 효과 반경이 0이면 단일 타겟 즉시타격, 0보다 크면 광역기가 되는 식으로 하나의 구조에서 양쪽을 다 표현. 판정은 **XZ 평면 거리 기준**(고저차 Y는 무시) — `Targeting.gd`(구 `Grid.gd`)가 이미 하던 평면 가정을 그대로 이어감, 고저차는 위 "사거리/시야" 섹션의 사거리·명중 보너스로만 별도 취급. 뼛조각 투척이 이 구조로 구현됨 — `ItemData.throw_range`(사거리, 범위 밖이면 던지기 자체가 거부)+`effect_radius`(효과반경, 범위 안인데 빗나가면 아이템/스테미나는 그래도 소모). 기본 근접 공격은 여전히 특정 대상과의 거리 체크(`INTERACT_RANGE`)로 남아있음 — 단일 타겟 스킬은 "빈 지점에 반경 0으로 조준"이 아니라 "대상 자체와의 거리 체크"로 구현하는 게 더 합리적이라고 판단.

## 열린 질문 (미정)
- 스테미나 소모 공식(이동 거리당 소모량, 등반 배율, 스킬별 소모량)의 정확한 수치 — 밸런싱 영역. 지금은 `CombatFormulas.MOVE_STAMINA_COST_PER_UNIT`/`BASIC_ATTACK_STAMINA_COST`에 플레이스홀더 값만 있음, 등반 배율은 구현 자체가 아직 없음(고저차 있는 지형이 없어서).
- 스테미나가 0이 되면 자동으로 턴이 끝나는지 — 지금 구현은 항상 수동 "턴 종료"만으로 끝남(자동 종료 없음), 재검토 여지 있음.
- 경로탐색(`NavigationAgent3D`) — 지금은 장애물이 없는 씬이라 직선 이동으로 구현, 실제 장애물이 생기면 필요. 절차적으로 생성되는 던전의 런타임 내비메시 베이킹 방식도 그때 같이 결정.
- 이동 범위 표시(`MovementRangeIndicator`)에 정확한 클램프 지점 프리뷰(호버 마커)를 추가할지 — 지금은 반경 원반만 보여주고 스코프에서 뺌.
- 엄폐(커버)의 구체적 판정 방식(레이캐스트 기반 세부 규칙, 부분 엄폐 여부 등) — 아직 구현 자체가 없음.
- 기량 구간별 속도 보너스의 정확한 구간 경계/증가폭 (밸런싱).
- 지형 상태(이동방해/상태이상) 종류 목록 및 장판 조작 아이템 체계 세부.
